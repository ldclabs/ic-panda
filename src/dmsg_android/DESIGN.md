## Brand & Style

The Android app keeps the information architecture of iOS — the same four
workspaces, names, order and flows — and takes its look and behaviour from
Android: Material 3 components, system bars, predictive back, a splash and a
themed icon. dMsg shows through colour, the mark, type weight and motion,
not by copying iOS chrome.

The base is quiet paper: pages are a low-chroma green-grey, cards are one
step lighter, and the forest green is kept for actions, selection and focus.
State colours (error, warning, verified) stay fixed and never follow the
wallpaper.

### Scope and Source of Truth

This file describes the theme as built:

| Concern | Source |
| --- | --- |
| Colour roles, `page`, `card` | `app/src/main/java/net/dmsg/android/ui/ThemeColors.kt` |

| `DMsgTheme`, `OnCard` | `ui/Theme.kt` |
| Window, splash and accent colours | `res/values{,-night}/theme_colors.xml`, `styles.xml` |
| Launcher, themed icon | `res/mipmap-anydpi/ic_launcher.xml`, `res/drawable/launcher_*.xml` |
| Shared components | `ui/kit/` |
| Business icons | `res/drawable/glyph_*.xml`, generated by `scripts/ios/sync-icons.py` |

When the code and this file differ, the code wins and this file is
corrected. The desktop keeps its own design file
(`src/dmsg_desktop/DESIGN.md`); both share the forest and gem brand colours.

## Rules

- **A1 Roles, not literals.** Pages take colours from `MaterialTheme.colorScheme`,
  corners from `MaterialTheme.shapes`, type from `MaterialTheme.typography` and
  margins from `pagePadding()` / `pageMargin()`. Literal colours, corners, sp sizes,
  monospace and whole-page padding live only in the theme files.
- **A2 Page and card.** The scaffold, top bars and sticky headers use
  `colorScheme.page`; a top bar turns `surfaceContainer` once the page scrolls
  under it. Grouped rows, detail cards and empty panels use `colorScheme.card`.
  Material components that default to `surface` (`ListItem`, `OutlinedCard`)
  blend into the page; inside a card or a sheet, wrap them in `OnCard` so they
  take the card colour. `Section` already does.
- **A3 One page margin.** 16 dp on phones, 24 dp once the window is 600 dp wide,
  on every side of a page and around its bottom actions.
- **A4 Identifiers look technical.** Account IDs, principals, fingerprints and
  digests use `code()`; one-time codes and countdowns use `tabular()`.
- **A5 Motion shows cause and effect.** Screen transitions, list placement and
  predictive back use the specs in `Motion`, defined once in `ThemeTokens.kt`;
  the system "remove animations" setting ends them immediately.
- **A6 The theme is provided once.** `DMsgTheme` wraps each activity; the only
  nested theme is `OnCard`.
- **A7 Pages compose the kit.** Grouped rows, list rows, banners, empty states,
  loading placeholders and filter chips come from `ui/kit/`; a page does not
  restyle them. Rows end with their value, a badge or a control, never a chevron;
  overflow menus use the vertical ⋮ icon.

## Typography

The Material 3 baseline scale on the system sans. Chinese, Japanese and
Korean drop the Latin tracking (letter spacing 0), which otherwise only
pushes ideographs apart. Large top bars show the title in `headlineMedium` and
collapse to `titleLarge`, the size of compact bars; list rows use `bodyLarge`
with `bodyMedium` supporting text; `bodySmall` is for metadata, not for
explanations. Aim for at most four sizes on one screen.

## Layout & Spacing

A 4 dp grid. `pagePadding()` gives the page margin on every side;
`pagePadding(top = 0.dp)` sits under a browse header, and a list under a
floating action button ends with `bottom = FabClearance` so its last row can
scroll clear of the button. The navigation bar takes its own space; nothing
scrolls beneath it. Bottom actions and sheet content use the page margin.
Cards pad their content by 16 dp; rows inside a section bring their own padding.

| --- | --- |

| `RowIcon` | A row's leading icon on a tonal circle; the section may colour it |
| `LabelValue`, `DetailCard` | A label with its value inside a card (`DetailCard` automatically applies `OnCard`) |
| `BrowseRow`, `BrowseIcon` | Compact rows of the vault, message and file lists, with a type glyph on a tonal square |
| `Avatar` | A round avatar: the image, an icon (the profile glyph for an unnamed account), or the first letter, on a container tone chosen by the account ID |
| `BrowseScopes`, `BrowseChoice`, `MenuChoice`, `SortMenu` | Filter chips that scroll sideways with fading edges, a chip that opens a menu of choices, and the sort chip |
| `Notice` | Inline banner, information or problem, actions at its end; at most one per screen |
| `EmptyState` | A mark, one line, one line of detail and at most one action, centred |
| `SkeletonRows` | The first read of a list; refreshes keep the content and show a thin bar |

Business icons are the desktop's Remix paths (`glyphs.ts`), shared with iOS:
navigation, vault item types, account rows, empty states and file actions use
them. `scripts/ios/sync-icons.py --check` compares the drawables and the vault
type mapping in `ui/kit/Glyphs.kt` with the desktop. Generic actions (search,
edit, copy, more) keep Material icons.

Compose previews are not provided: `DMsgTheme` and `str()` read the app
language from the running application. `KitGalleryTest` renders the kit on a
device in light, dark and right-to-left at 200% text, checks 48 dp touch
targets and saves screenshots under the app's external files (`kit-gallery/`).

## Navigation and Page Chrome

- **Navigation bar.** Phones show the Material 3 `ShortNavigationBar`, flat and
  full width on `surfaceContainer`, on workspace roots only; windows from
  840 dp show the collapsed `WideNavigationRail` instead.
- **Bars belong to pages.** `DMsgApp` frames every page with its own bar inside
  the page transition, so a title moves with its page. On phones a workspace
  root shows its search field as the top bar, with the activity bell and ⋮
  inside it. Wide roots, conversations and open files keep a compact
  `TopAppBar`; every other page, a vault item included, has a `LargeTopAppBar`
  that collapses as the page scrolls. Titles come from the route table in
  `DMsgApp.kt` unless the page declares its own with `ScreenBar`, which also
  adds the page's actions. On wide windows the detail pane (`DetailPane`) has
  its own compact bar for them.
- **The activity bell** sits on workspace roots and the scopes beside them
  (Letters, Cloud backups), never on sub-pages.
- **One floating action.** A page declares its primary action with `ScreenFab`:
  New item in the vault, New conversation in messages, Write a letter in
  letters, Import files in files.
  The extended FAB collapses to its icon once the list scrolls. It hides its
  text from accessibility, so the icon carries the same label.
- **Work in progress** shows as a thin bar across the top of the page instead
  of a reserved strip.
- **Full-screen forms.** The vault editor is a full-screen dialog: Close at the
  start of its bar, Save at the end. Secret inputs carry Show and Generate as
  trailing icons.

## Vault

- **List.** Filter chips for All, Favorites, Passwords and Notes, a Type chip
  that opens the remaining types, and the filter sheet: sort as a radio list,
  tags as chips, Clear filters and Done at the bottom. Rows waiting to sync show
  a small sync icon in the secondary text colour.
- **Item.** The title is the large page title; favourite and edit sit in the
  bar and ⋮ holds version history, sharing and Move to trash (in the error
  colour, confirmed by a dialog). Below the type and sync state, at most one
  banner (conflict, trash, historical version, managed key). Fields keep their
  sections as grouped rows: a tap copies, trailing icons reveal, open the website
  and copy (the copy icon turns into a tick), and a long press offers large type
  and the field reference. One-time codes show a countdown ring. Item
  information shows relative times ("3 minutes ago", "Today at 07:21"); a tap
  shows the full date and time.

## Motion

material3 1.4.0 keeps `MotionScheme`, `MaterialTheme.motionScheme` and
`MaterialExpressiveTheme` internal, so its components animate with the
standard scheme and the theme cannot replace it. The app's own animations take
their specs from `Motion` in `ThemeTokens.kt`, the Material 3 expressive spring
values in the front matter: movement may overshoot slightly, fades and colour
changes never do. `UiConventionsTest` rejects literal specs elsewhere.

- **Pages** move along a shared horizontal axis: forward slides 30 dp in from
  the end while fading in, back from the start; switching workspaces fades
  through. A page keeps its composition while only its selection or folder
  changes, so split panes update in place; on phones a vault item or a
  conversation opens as a page of its own. Pages read their own route, never
  the navigation's current one, so a page that is leaving keeps its content.
- **Predictive back** scrubs the back transition with the gesture
  (`SeekableTransitionState`), so the parent page and its bar show as the
  finger moves; cancelling returns and releasing completes the transition.
  Routes that update a shared pane keep its selection until the gesture commits.
- **Lists** move inserted, removed and reordered rows with `animateItem()`;
  so do a conversation's messages, queued ones and the attachments above the
  composer.

The small motion follows the desktop's seven verbs
(`src/dmsg_desktop/docs/motion.zh.md`) with the kit in `ui/kit`:

- **Making room.** `Reveal` opens a block downwards and closes it again; the
  rest of the column moves with it. Status lines (a failed or stale read, the
  refresh bar, a conversation's sync error), the reply card and the attachments
  above the composer use it; `retained()` keeps the last content drawn while it
  leaves. A first read keeps its skeleton without a transition.
- **Floating.** The in-app reminder card drops 16 dp into place and fades out;
  covering the screen hides it at once. Work in progress fades in at the top.
- **Counts.** `Count` rolls only the digits that changed, up as a count grows,
  inside its own bounds and left to right in every language. `CountBadge` pops
  in when a count leaves zero and shrinks away at zero; `DotBadge` does the same
  for the activity dot.
- **Copies** confirm in place: `CopyButton` turns its icon into a tick and its
  label into "Copied" for two seconds and keeps its width; `CopyIcon` and
  `CopyIconButton` do the same for icon-only copies. Menu copies, which close,
  are left to the system's clipboard confirmation.
- **Developing.** A revealed vault value and each new one-time code develop
  from a 6 dp blur (`Modifier.develop`); hiding is instant. The code ring
  follows the code's expiry and fills at once for a new code.
- **Settling.** Chips move their tick and colours together; a favourite star
  springs in (`spatialFast`) when set and fades when cleared; the send button
  grows in; the entry mark grows in where the splash icon was. Progress bars
  glide to their value (`Progress`); an avatar's picture fades in over its
  initial.
- **Haptics answer results:** Confirm for a copy and a finished approval,
  Reject for a failed send and a refused package preview, toggle ticks for
  switches, favourites and segmented choices, a long press as the message sheet
  opens. Counts and arriving messages do not buzz. System animator scale 0
  turns the motion off.

## Messages

- **Lists.** Conversations and letters lead with an `Avatar`. Unread rows set
  the title in bold, the preview in the body colour, the time in primary and a
  count badge. Times read as a clock today, a weekday this week and a short
  date before; a missing time shows nothing. A draft reads quieter, in
  italics after "Draft:".
- **Conversation bar.** Avatar, name and "Encrypted conversation", with Search
  and ⋮ (conversation settings). There is no manual refresh. A sync error shows
  once, as a banner under the bar that can be closed.
- **Bubbles.** Consecutive messages from one sender on one day form a group:
  2 dp apart, the sender named once, and the corners next to the neighbours
  tucked in (`bubbleShape`). Time and Edited sit at the bubble's tail. A
  reply quote and the reply preview above the composer carry a primary accent
  bar (`QuoteBar`).
- **Actions.** A long press opens the actions sheet (reply, copy, edit,
  withdraw, report, block); a tap does nothing. TalkBack offers the same
  actions as a long-press action.
- **Composer.** A filled capsule holds the attachment menu and the text; the
  attachment button, the last text line and the send button share one centre
  line. The send button grows to full size once there is something to send.

## Account, Entry and Files

- **Account root.** A large bar; the identity card on the card colour with the
  account's `Avatar`, name, "Public profile" and the plan chip. Waiting
  approvals show as a badge. Appearance is its own group: the theme as a
  `SegmentedChoice` (System, Light, Dark), dynamic colour (off by default; the
  wallpaper scheme with the page one container step down so cards stay
  lighter, and the app's own error roles) and the app language. Sign out is a
  red row in a group of its own and asks before it acts.
- **Entry and lock.** No card: the mark grows in where the splash icon was,
  the greeting and one primary action sit centred, and a locked workspace
  shows the account's avatar and saved name (or its ID in `code()`) under
  "Welcome back". Explanations sit under the action they belong to as small
  centred text; banners are for errors. Saved accounts, language, privacy and
  about are one row of small links at the bottom edge.
- **Files.** The encryption note is the empty folder's hint and is not repeated
  under a filled list. A grid view waits for cached thumbnails: each thumbnail
  is decoded from the file's preview, and a grid would multiply that work.

## Platform

- **Splash.** The platform splash (API 31) shows the adaptive icon on the page
  colour of the current system appearance, stays while the local engine opens
  (at most two seconds), then fades out while the icon grows slightly.
- **Night theme.** `values-night` switches the window, status and navigation bar
  appearance before the first Compose frame. The in-app appearance setting
  applies from the first frame; the splash follows the system setting.
- **Themed icon.** The adaptive icon has a monochrome layer: the mark with the
  gap around the gem cut out, so the launcher can tint it.

## Checking a Change

1. `./gradlew :app:testProductionNoneDebugUnitTest` (or the variant in use) runs
   `ThemeColorsTest` and `UiConventionsTest` with the other JVM tests.
   Do not widen `UiConventionsTest` allowances to make a change pass.
2. Compare screenshots before and after in light and dark on the emulator:
   a root workspace, a detail page, a settings group, a sheet and a dialog;
   add Chinese, Arabic (RTL) and 200% font size for layout changes.
   `AccountNavigationFlowTest` steps the page transition and the back gesture
   with the test clock; a screen recording of a loaded emulator drops frames
   and cannot show them.
3. Walk the visual acceptance checklist on the pages the change touches:
   - corners and colours come from the tokens (`UiConventionsTest`);
   - one page margin (`pagePadding()` / `pageMargin()`);
   - at most four type sizes in a page's bar and content, not counting the
     navigation bar;
   - one primary action: a FAB or one filled button;
   - at most one banner, and only for a problem or a state the reader must act on;
     explanations sit under their control;
   - moving between pages animates along the shared axis;
   - the card is lighter than the page in light and dark;
   - beside the matching Android 16 Settings page or Google app on the same
     emulator, nothing reads heavier or busier.
4. `scripts/android/verify.sh device` ends by pulling the current run's captures
   (`/sdcard/Download/dmsg-*`, including the kit gallery) into
   `app/build/reports/dmsg/screenshots/`; keep the run from before a visual
   change and compare the two directories, and attach before/after pairs to
   the pull request.
5. Report what was run and what was not.

## Known Gaps

- Dialogs use the Material defaults (`surfaceContainerHigh`, 28 dp).
- With dynamic colour on, the launch window and splash keep the brand page
  colour, so the first frame changes colour once Compose draws.
