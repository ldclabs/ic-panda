# Landing and legacy archive integration

The marketing route is isolated from legacy authentication and token-price initialization. It preserves the original IC asset canister `index.html` SPA fallback so existing `/[handle]`, `/_/[channel]`, profile and authentication URLs remain routable.

The root route loads the initial language catalog before rendering, so SvelteKit can locate fragment targets and restore scroll. The static HTML includes an English title, description and share image; the client localizes the existing description in place and supplies default/page titles without duplicate metadata.

## What the page claims

The page follows `DESIGN.md`. It describes dMsg as one local program, `dmsg`: a daemon that holds the keys and the approval queue, reached by the desktop app, the command line, AI agents over MCP and websites through `connect.dmsg.net`. There is no browser extension. The desktop app and command line are released. The platforms are those of the `dmsg-v*` release assets: the desktop app for macOS on Apple Silicon and Windows x64, the command line also on Linux x86_64 and arm64; Windows is marked less tested because the release workflow does not verify Windows builds yet. The download buttons point at `releases/latest/download/dMsg-mac-arm64.dmg` and `dMsg-win-x64.exe`, the repository's latest release is always a `dmsg-v*` release, and the install commands install the latest release, so the copy names no version and a new release needs no page change. `/legacy` remains the read-only entry for old messages; migration starts in the desktop app under Settings › Legacy, which the FAQ, the release section and the support page say.

Facts on the page come from the public code and its READMEs: the 65 tools of `dmsg mcp` (33 standard Agent Protocols tools and 32 `dmsg_*`, `src/dmsg_agent/src/tools.rs`), the 26 agent capabilities (`CAPABILITIES` in `src/dmsg_client/src/agents.rs`; public profiles need no grant), the capabilities no agent can hold, the `dmsg` commands and output shapes, the approval sources `gui`/`cli`/`agent:`/`connect:`, the second click before a secret is shown or copied, the 15-minute idle lock, recovery by a bound login after a one-to-seven-day disputable delay, and the dmsg-connect/1 moves and trust point.

The vault holds notes, logins, API keys and keys; files live in the file library (`src/dmsg_cli/README.md`, Files, Backups, Links, Mount): files stay on the device, up to 4 GiB each; only Back up uploads, as `kind=backup` objects under random IDs and at most 100 MiB a version; deleting on one side never reaches the other; the trash keeps 30 days; a share to a channel or by link is a fresh copy under its own key; an opened copy goes after 30 minutes or on lock; the library can be mounted as a disk; agents get `files.read|write:<folder>`, and no tool backs up, shares or deletes. Team wallets follow `docs/protocol/wallet_zh.md` and `src/dmsg_wallet/README.md`: one canister per team; ICP and ICRC transfers by the canister and threshold signatures for Bitcoin, EVM chains and Solana; spending tiers by amount with approvals and a 24-hour delay any approver can veto; an address book whose new entries wait; agents propose and execute (`wallet.propose`, `wallet.execute`) and no capability approves; cosigned addresses (Secure Enclave on a Mac) and dual-control Taproot addresses; creation needs a paid plan and a one-time ICP activation. The page says wallets are in development and not audited. The file library and team wallets landed on main after `dmsg-v0.1.0`; by choice the page shows them without a version. No audit, user count, signature, payment, backup or wallet deployment is claimed. The hero's Agent Protocols copy follows `src/dmsg_agent/README.md` and `src/dmsg_cli/README.md` (Agents, `dmsg mcp`): each hosted agent has its own Agent ID whose key is a vault item (resident only if allowed); its Discourse, Mail and Knowledge calls need `discourse|mail|knowledge.read|write` grants for an origin and are signed with the Agent ID; `agent grant` signs a delegation with the account's controller after approval, and the delegation service is the relay (`api.dmsg.net`).

The desktop section follows `src/dmsg_desktop/README.md`, `src/dmsg_desktop/DESIGN.md` and `src/renderer/shell/nav.ts`: the sidebar's groups (Work: Channels, Files, Vault, Inbox; Authorization: Signatures & approvals, Agents; Account: Team wallets, Plan & names left out) in the app's order with ⌘1–⌘8, the views' one-line descriptions in the app's own words and translations, the gate rail (lock state, sync, Lock), the command palette (⌘K, Ctrl+K elsewhere), light, dark or the system's appearance, six languages with Arabic right to left, and the tray. The idle lock is `idle_lock_minutes = 15` by default and fast unlock keeps its key in the Secure Enclave with Touch ID on macOS (`src/dmsg_cli/README.md`). A secret shows or copies only on a second click and a copied secret's notice counts down to the clipboard being cleared (desktop DESIGN, Secret field). The Inbox's contact rules are nobody, contacts only, everyone and paid letters, and payment covers delivery, not a reply. The approval window holds Approve back for 1.2 seconds and a payment is approved by holding it for a second (desktop DESIGN, R5); the hero's figure does the same. The trust section links the in-browser verifier at `/_/verify`. The figures use `example.com` as a website's origin; no partner site is named in the hero or the tour.

## Figures

Every figure runs in the browser with sample data and says so in its label. None contacts a service.

- **The gatehouse** (`HeroArt.svelte`, scene in `hero-art.js`, shared with the six social cards): the mark drawn flat on its own 42 × 48 grid (the paths of `mark.svg`, no gradient or shadow) with five rooms in its dome: vault, files, channels, team wallets and the agent's Agent ID. You (desktop and terminal), Mei (a teammate), `release-assistant` (your agent) and a website (`connect.dmsg.net`) ask on the left; their traces rise over the post and drop down the gap without crossing. Agent Mail, Discourse and Knowledge, with their production hosts from `src/dmsg_client/production.toml`, sit on the right. A scripted round sends Mei's message to Channels, the visitor's own item to the Vault and the agent's write to Files (each trace draws behind its packet, a ring leaves the gem, the room lights), then the agent's letter to a host: through the gap to the Agent ID room, which lights as it signs, back to the gem and down the gap on the dashed wire. Then a request stops at the gem, rotating among a release statement to sign, a sign-in to `example.com` and a 0.4 BTC payment from the team wallet; two rings mark it and one drains over 15 seconds. The approval window under the scene shows the kind, the source (`agent:` or `connect:`), what approving does, an expiry bar, Reject and Approve (Hold to approve for the payment); every state shares one grid cell so the window keeps its height. Approving sends a signature or sign-in result back up the trace to the asker, which gets a check, or a vote into Wallets; rejecting or letting it expire says nothing was signed, paid or approved. A log beside it keeps the last three events, and the idle window says “Approved without you: 0”. The scene runs on a clock that advances only while it plays: the pause button, scrolling it out of view or hiding the tab stop it. Below 560px the scene switches to a narrow layout with the network under the gate, and the approval window comes first. With reduced motion the scene is still, a request already waits, and each decision brings the next.
- **The desktop app** (`DesktopTour.svelte`): the main window with its sidebar, gate rail and title bar with the palette; each view shows one glance with sample data (a channel with an agent's message, files and their backup states, a login with its one-time password, contact rules and letters, requests waiting and decided, agents with their capabilities and an audit record with a `FORBIDDEN`, a team wallet proposal). The tour advances every 5.6 seconds while on screen and not hovered, focused or chosen by the visitor; Lock shows the locked state with Unlock with Touch ID.
- **The project story** (`CollaborationStory.svelte`) and **the agent network** (`AgentNetwork.svelte`) are step-by-step examples; the story plays only when asked and shows each step's time running out on its tab.
- **Desktop and terminal** (`DeviceDuo.svelte`): one simulated daemon behind a desktop window and a terminal that accepts a few `dmsg` commands (`status`, `vault list|show|add`, `lock`, `unlock`, `attest file`, `approvals list`, `help`). The window's sidebar lists the desktop's views, Files and Team wallets included; the vault has no file items. `attest file` opens the approval sheet in the window; either side can decide. Locking in one pane is enforced in the other.
- **Files** (`FileLibrary.svelte`): the library on this device beside what the cloud holds. Back up asks first with the room it takes, then uploads under a random ID; a trashed file keeps its cloud copy; deleting a cloud copy takes a second click and leaves the file; a backup from another device gets its name only when fetched. “Uploaded without you” and “Deletions that crossed over” stay 0.
- **Team wallets** (`TeamWallet.svelte`): a BTC transfer an agent proposed for a member. The amount picks the tier (1 of 2 approvals, or 2 of 2 and a 24-hour delay); the visitor approves or rejects, plays the second approver, vetoes or skips the delay, and executes: the wallet signs, the device broadcasts, the proposal settles, and every step lands in a hash-linked audit chain. A rejection turns it down only once too few approvers remain. Nothing happens without a click.
- **Agents** (`AgentPlayground.svelte`): capability switches, a scripted MCP run whose calls succeed or fail with `FORBIDDEN` according to the switches (a file-library write among them), and an audit record of grants and calls.
- **Websites** (`ConnectFlow.svelte`): the dmsg-connect/1 sequence, which stops at the approval window until the visitor approves or rejects.
- **Privacy** (`CipherLanes.svelte`): the visitor's text is encrypted in the browser with a throwaway AES-GCM key to show what the cloud holds, including its size; the note says dMsg's own format differs.

With `prefers-reduced-motion: reduce` the figures show still scenes that remain interactive, the headline and sections appear without motion, and smooth scrolling is off.
