## 1. 我们的宗旨

ICPanda DAO 是一个链上**建设者 DAO (Builder DAO)**：一个利用共同治理、受治理的资本与工程研发能力来构建开放基础设施的社区。

我们的探索始于一个务实的根本问题：**随着软件承担越来越多的工作与经济职责，其身份、记忆、资产与授权究竟归谁所有和掌控？**

AI Agent 能够调用工具并执行受托任务，但其身份与沉淀的经验往往被死死锁在单一应用之内。加密技术赋予了资产可编程性，但构建可信的经济体仍需要透明的发行、分发与治理机制。使用这些系统的人们，同样需要对自身共享和授权的内容拥有绝对的掌控权。

我们将在参与数字系统的同时保留实质性掌控权的能力称为**数字主权 (Digital Sovereignty)**。它涵盖可移植的身份与记忆、可验证的所有权与交换，以及对共享资源的透明负责任治理。

ICPanda DAO 通过三大互补的建设方向践行这一愿景：

| 建设方向                                      | 核心目标                                                                           |
| --------------------------------------------- | ---------------------------------------------------------------------------------- |
| **Anda —— 主权心智 (Sovereign Minds)**        | 帮助智能系统跨越时间与具体应用，完整传承身份、记忆、经验与技能。                   |
| **TokenList —— 主权市场 (Sovereign Markets)** | 让代币化经济体的资本募集过程变得公开透明且切实可验。                               |
| **dMsg —— 个人控制 (Personal Control)**       | 为人们提供专属的隐私工作空间，用于私密保管、加密协作以及跨应用程序的明确签名授权。 |

**PANDA** 通过 SNS 治理、金库资金配置与社区协同，为支撑这项工作的组织实体提供核心动力。

每一个项目都独立解决一个极具实用价值的具体问题。它们的共同航向，是打造一套让人类与 Agent 能够携手协作的基础设施，具备可移植的状态、可审查的规则与清晰明确的授权。

## 2. Anda —— 主权心智

[Anda](https://anda.ai/) 致力于为机器持久认知构建开放协议与基础设施。其核心目标是让智能系统在底层模型、运行时环境与上层应用不断变迁的过程中，依然能够持续传承和运用宝贵的实践经验。

### 能够改变行为的记忆机制

单纯的对话历史可以记录发生过什么，却无法帮助 Agent 决策下一步该做什么。真正实用的记忆系统必须能够保留上下文、区分客观证据与主观信念、追踪状态演变，并切实影响未来的行为判断。

> **记忆，是让过去参与未来计算的核心机制。**

不妨对比以下两种情形：办公室从 A 栋搬到了 B 栋，与序列号从 AX-19 勘误修正为 AX-91。前者记录的是现实世界的客观事实变化；后者则是对过往记录错误的纠正。如果仅仅保留最新的文本快照，这种本质差异就会彻底丢失。

从行动中学习同样遵循此理。Agent 需要完整记录目标意图、尝试采取的行动、过程观测、原因诊断、纠偏恢复以及最终产出。记忆模型明确区分了三个紧密关联的概念：

- **知识 (Knowledge)** 提炼普遍成立的客观规律与事实；
- **经验 (Experience)** 留存产出特定结果背后的完整流程与约束条件；
- **技能 (Skill)** 将经验中汲取的教训固化为可复用的行为能力。

完备的记忆系统应当保留事实来源出处与不确定性，在证据发生变化时动态修正既有信念，并能区分对某个断言的置信程度与该断言被检索唤起的容易程度。它还需要具备记忆整合、遗忘与经验迁移的能力，避免将旧有的教训生搬硬套到不适用的新场景中。

### 开放的组件架构

Anda 通过一系列可独立采用的模块化组件来解决这一难题：

| 核心组件                                                                                      | 职责定位                                                                                   |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **[KIP —— 知识交互协议 (Knowledge Interaction Protocol)](https://github.com/ldclabs/KIP)**    | 持久认知状态的通用标准模型，涵盖命题、信念、证据、时间有效性、来源溯源、经验与技能。       |
| **[Agent Protocols (Agent 互操作协议)](https://github.com/ldclabs/agent-protocols)**          | 可验证的 Agent 身份标识、能力描述以及跨系统的认证交互规范。                                |
| **[Anda Runtime (主权运行时)](https://github.com/ldclabs/anda)**                              | 采用 Rust 构建的高性能可组合基础运行时，支持 Agent、工具、技能、编排及面向隐私的执行环境。 |
| **[Anda DB (认知记忆数据库)](https://github.com/ldclabs/anda-db)**                            | 融合结构化、语义向量、全文检索与知识图谱的多模态记忆基础设施。                             |
| **[MIB —— 记忆智能评测基准 (Memory Intelligence Benchmark)](https://github.com/ldclabs/MIB)** | 用于衡量记忆是否切实改善智能系统未来认知与行为表现的开放评测基准。                         |

身份确立了 Agent 的主体归属与控制权限；记忆维系了其跨越时间的认知连续性。两者都应当能够超越单一平台的束缚而自由流转。

MIB 评测涵盖记忆检索、时间推理、证据与不确定性理解、经验沉淀、技能迁移以及记忆对后续行为决策的因果影响。其核心命题是：相关的历史经验能否切实提升后续决策质量，同时对过时陈旧或有害的记忆保持抵御能力。MIB 保持架构中立，参与评测无需强制绑定 KIP 或 Anda。

协议规范、工程实现与评测基准保持充分解耦，以便其他开发者构建替代方案并共同验证底层理念。

## 3. TokenList —— 主权市场

[TokenList](https://tokenlist.ing/) 为**可验证的加密资本募集 (Verifiable Crypto Capital Formation)** 构建基础设施：涵盖资产从创建、分发、交易到最终由社区共同治理的全过程。

创建代币仅仅是第一步。一个良性运转的经济体，还需要可信的分配机制、公允的价格发现、充足的流动性，以及对共有资金与治理权限如何使用的清晰交代。

TokenList 的长期范畴遵循以下完整生命周期：

**创建资产 → 规则发行 → 价格发现 → 建立市场 → 社区协作 → 走向治理**

参与者应当能够自主审查所发行的资产与供给量、参与准入与分配规则、价格形成机制、募集资金的流向，以及底层执行是否与既定规则完全相符。随着代币所有权走向分散，社区还需要配套机制来共同治理其生态金库并持续演进底层基础设施。

### 供检验与迭代优化的市场机制

连续清算拍卖 (Continuous Clearing Auction, CCA) 是服务于这一方向的关键机制之一。它允许真实需求在预设规则下随时间推移共同参与价格发现。其机制价值取决于具体设计，包括时间窗口、信息透明度与分配方式如何影响各方参与者。

随着实践证据积累与需求演进，TokenList 对各类市场机制保持开放。其根本原则是：让资本募集的规则完全公开可审查，让规则的执行切实可验证。

单纯的可验证性本身并不能直接等同于公平性、经济可行性或法律合规性。发行方与参与者仍需对其适用的法规要求负责，上层应用也需具备恰当的风控机制。透明的执行过程赋予了参与者更坚实的事实依据，以便其客观评估市场。

## 4. dMsg —— 个人控制

[dMsg](https://dmsg.net/) 正在从早期的加密通信实验进化为一款**用于隐私工作与跨应用签名的 Chrome 浏览器扩展**。新架构设计已明确确立；具体实现、部署上线、安全审计与发布验证正在稳步推进中。

规划中的工作空间始于个体核心诉求，并自然延伸至团队协作：

- **个人保险库：** 便签、凭据、密钥材料与文件均在本地加密，支持本地全文搜索与加密导出；
- **加密协作：** 用于消息与文件传输的隐私频道，具备明确的成员管理、发布角色划分与历史记录访问控制；
- **联络规则：** 联系人管理、邀请制、黑名单，以及针对未受邀请求的可选代币付费接收门槛；
- **身份与签名：** 持久稳定的数字身份，对文件、声明与授权操作进行显式交互确认签名。

浏览器扩展是完整的工作空间承载体，在已授权的多台设备之间进行端到端加密同步。官方网站仅承担公开主页展示、签名有效性验证以及安装访问引导的功能。

### 架构分工与信任模型

系统设计清晰拆分了三层职责：**浏览器扩展**负责明文处理、加解密运算与签名确认；**Cloudflare** 负责存储密文并支撑日常协作与消息分发；**ICP (互联网计算机)** 负责维护身份根与恢复根、设备管控、正式门限签名权限、域名所有权解析以及链上支付结算。

日常消息传输与频道更新无需触发区块链状态变更或门限签名。带有密码学签名的控制记录使得客户端能够独立验证是谁授权了对共享内容的修改。

内容解密密钥始终保留在已授权的终端设备上，Cloudflare 仅能获知维持运营所必需的元数据。签名可验证控制事件的真实性，但无法保证云端总是呈现最新的历史记录或撤销状态。服务可用性、扩展版本更新以及 Canister 升级权限依然构成信任依赖。开源发布模型将客户端代码、协议规范、Canister 合约与数据恢复工具完全开源；生产环境的云端运营实现则保持独立运作。

### 权限控制、数据恢复与权利延续

授权模型严格区分了应用登录、查阅共享内容、管理关联设备与批准正式签名。连接第三方应用仅授予受限的选定能力；正式签名必须对请求来源、用途与载荷进行显式确认。

规划中的 TokenList 集成将对固定版本的文件声明进行签名，并返回独立可验证的凭据证据。TokenList 独立保留其项目角色与发布权限控制：单凭签名本身无法确立业务层面的授权有效性或内容的真实性。

独立的内容恢复依赖于完整的加密备份与单独保管的恢复材料。登录恢复、内容恢复与门限私钥控制权彼此解耦。撤销设备会立即阻断其发起新的敏感授权。保护后续新内容需要完成相应的密钥轮换；而已被该设备接收并解密的旧数据无法远程抹去。

在规划的付费联络流程中，外部请求费用仅购买投递接收，并不包含已读或回复的承诺。链上资金托管合约负责最终结算与超时退款，在结算未获授权的情况下，超时即可直接退款，无需云服务运营商介入批准。

服务运营模式采用存储、流量、签名调用与平台服务费。基础使用无需强制购买靓号 Handle、消耗 PANDA 或挖取 DMSG。早期的历史数据与代币相关权益将通过专门的迁移与治理流程妥善处理。

## 5. DAO 与 PANDA

ICPanda 始于 Meme 文化。一只辨识度极高的可爱熊猫将志同道合的人们凝聚在一起；SNS 治理机制则赋予了这个社区共同调配共享资源的制度能力。在通信、存储、密码学、Agent 基础设施与代币发行机制上的持续探索，逐步孕育出了本文所阐述的长远使命。

组织机构得以历久弥新的根本目的，在于持续学习进化、合理配置资源并坚持不懈地建设。具体的产品可以迭代演进或体面终止，而它们沉淀的源代码、开放协议与经验教训将永远留存并赋能后来的建设者。

### 治理与协同

PANDA 是 ICPanda DAO 的治理与协作资产。它承担三大核心功能：

- **治理 (Govern)：** 持有者可以将 PANDA 质押锁定在 SNS 神经元 (Neuron) 中，在现行投票规则下参与提案表决；
- **配置 (Allocate)：** 治理投票决定将 DAO 控制的资源配置于前沿研发、工程构建、安全审计、日常运营及其他经批准的工作；
- **协同 (Coordinate)：** 社区能够围绕共同的目标，凝聚建设者、贡献者、用户与生态合作伙伴。

互联网计算机的 **Service Nervous System (SNS)** 提供了链上原生治理框架。其治理效力适用于其控制下的资源与基础设施；与 ICPanda DAO 关联并不意味着每一个项目组件都会自动受控于 SNS。

领导力与专业知识始终不可或缺。建设者需要充分的空间来做出技术与工程运营层面的决策，而对共有资源的掌控权则必须公开透明、有迹可循。单靠代币投票并不能天然保证去中心化或明智的判断。

PANDA 的新实用场景应当在能够切实改善真实系统时自然涌现，绝不应为了证明代币存在合理性而凭空捏造虚假需求。

### 核心建设原则

- **默认开放 (Open by default)：** 公开发布实用的代码与协议，以便他人自由审查、扩展并在此基础上继续构建；
- **证据优先 (Prefer evidence)：** 在一切可行之处实现主张的可验证性，并坦诚披露依然存在的信任假设；
- **保留选择 (Preserve choice)：** 坚持可移植性与互操作性，确保人们能够自由地在不同系统之间迁移数据、身份与社交关系；
- **负责任地使用资源 (Use resources responsibly)：** 基于客观实际评估各项实验，果断停止不再具备投入边际价值的工作，并妥善留存可复用的知识资产。

这些原则既适用于具体的产品，也同样适用于建设者组织本身。渐进式的开放要求公开构建过程、透明的金库决策、清晰明确的责任担当，以及能够产生实质约束力的治理机制。

PANDA 于 **2024年4月3日** 通过互联网计算机 SNS 正式发售启动，创世总供应量为 **1,000,000,000 PANDA (10亿枚)**。

| 分配对象                | 份额占比 |        PANDA 数量 |
| ----------------------- | -------: | ----------------: |
| 研发团队                |       4% |        40,000,000 |

最初的金库规划中，创世总量的 50% 计划通过 Lucky Pool 分发给社区，社区激励、CEX 上所激励与 DEX 流动性各占 10%。后来的持币者空投通过 SNS 治理提案使用了部分社区分发额度。

上述数据客观记录了历史分配与最初意图，绝不能被误读为对当前个人持仓分布或金库实时余额的表述。

### 治理奖励与代币供应

截至 **2026年9月7日** 查询的 SNS 奖励参数如下：

| 参数项             | 数值 |
| ------------------ | ---: |
| 初始年化奖励基准率 |   8% |
| 最终稳定年化奖励率 |   4% |
| 平滑过渡周期       |  2年 |

SNS 释放曲线在初始利率与最终利率之间采用二次曲线平滑衰减。过渡期结束后，奖励率将保持在 4%，除非后续由治理提案修改。这些均属于可治理的状态参数，而非永恒不变的货币常量。详见 [SNS 配置参考文档](https://docs.internetcomputer.org/references/sns-settings/#voting-reward-settings)。

治理投票奖励首先以神经元成熟度 (Maturity) 的形式累积。只有当成熟度被主动铸造转化时，才会增发生成新的 PANDA 代币。因此，奖励率描述的是整体奖励资金池的增长基准，而非对单个持币者的收益保底承诺，亦非固定的供应量增长率。实际供应量取决于成熟度铸币操作、账本的其他流转活动以及社区治理决策。

**在现行奖励参数下，PANDA 在协议层未设立固定的最大硬顶供应量。**

截至 **2026年9月7日**，PANDA 实际总供应量约为 **10.771 亿 PANDA**。此数值仅为特定时间节点的事实快照，有别于创世供应量与流通供应量。若需查询最新的实时供应量、金库余额、神经元分布、治理提案与运行参数，请访问 [ICPanda SNS 治理仪表板](https://dashboard.internetcomputer.org/sns/d7wvo-iiaaa-aaaaq-aacsq-cai) 及其底层的账本与治理 Canister 智能合约。

## 7. 宏大视野

我们的长远探索聚焦于三大核心命题：

1. **持久机器认知 (Persistent Cognition)：** Agent 能否跨越时间、模型与运行时环境，持续保有并动态修正有价值的实践经验——我们又能否证实这切实改善了其后续行为？
2. **可验证资本募集 (Verifiable Capital Formation)：** 参与者能否清晰审查并验证资产全生命周期的每一个环节——从规则发行、价格发现到金库构建与自治治理？
3. **人机自主协同 (Human–Agent Coordination)：** 人们能否将工作流与经济操作安全委托给软件，同时保留明确的终极授权与透明可查的决策证据链？

这三大命题深刻解释了为何这些项目密不可分。一个 DAO 可以借助 Agent 进行提案调研、保全证据链并协助处理已获授权的工作流。这必然需要记忆体系与身份支撑、可验证的经济规则，以及面向参与个体的清晰权限控制。Anda、TokenList 与 dMsg 正是分别从互补的维度满足这些系统需求。

这是一个面向前沿研究与生态集成的演进方向，而非宣称一套现成的完美系统已经就绪。开放的标准接口允许其他独立项目自由接入，而无需强制采用完整的 ICPanda 技术栈。

具体的路线图与工程实现会随时间不断演变。衡量子系统进展的终极标尺，应当是它是否提供了切实有用的基础设施、是否有充分事实证明其行之有效，以及它赋予了用户与社区多少真实的自主掌控力。
