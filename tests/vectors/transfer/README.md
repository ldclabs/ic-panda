# dMsg device transfer vectors

Byte rules of `dmsg-device-transfer/1` (the public contract is
[device_transfer.md](../../../docs/protocol/device_transfer.md)). The file is
generated by the Rust implementation, compared on every test run, and
rewritten with `DMSG_WRITE_TRANSFER_VECTORS=1`. All keys, devices and the
account are synthetic and test-only.

| File | Content | Generator and reader |
| --- | --- | --- |
| `transfer-v1.json` | The advertised Bonjour name, two manifest entries and the manifest digest, the HPKE info, the hello (header CBOR, signed digest, Ed25519 signature, framed bytes) and one frame of every body with its AAD and AES-256-GCM bytes | `dmsg_client` `transfer::tests::transfer_vectors_match` and `the_vectors_verify_and_open` |

```sh
cargo test -p dmsg_client transfer::
# after an intended change:
DMSG_WRITE_TRANSFER_VECTORS=1 cargo test -p dmsg_client transfer::tests::transfer_vectors_match
```

## Conventions

- `*_hex` fields are lowercase hex; `*_cbor_hex` is canonical CBOR.
- The HPKE ephemeral key is derived from `ekm_hex`, so the sealed key is
  reproducible; the session key is `keys.session_key_hex`.
- A frame's nonce is `direction ‖ 0x000000 ‖ sequence` (big-endian), and its
  AAD is `aad_hex`. Readers rebuild the AAD from `direction` and `sequence`,
  open `sealed_hex` with the session key and compare the plaintext with
  `body_cbor_hex`.
