# dMsg client vectors

Language-independent byte rules of the dMsg client. Work package W0 exported
most files from the browser extension, which W9 deleted (it was last present in
ic-panda `37451040`); the Rust client (`src/dmsg_client`) must reproduce or open
every item here. `login-v1.json` and `connect-v1.json` are generated by the Rust
implementation. All keys, seeds and accounts are synthetic and
test-only.

| File | Content | Rust test |
| --- | --- | --- |
| `primitives-v1.json` | Canonical CBOR encodings and rejections, base64url, Xid, `D(K, C)`, the local unlock key, COSE_Encrypt0 seals and rejections, HPKE with a fixed ephemeral key, Ed25519 | `codec::tests`, `crypto::tests` |
| `content-v1.json` | Encrypted objects (new, edited, tombstone, file entries), the cloud object container, file chunks and the chunk nonce rule, upload manifests | `content::tests::opens_exported_objects`, `opens_exported_manifests`; `files::tests::reproduces_file_chunks`, `reads_exported_files` |
| `root-v2.json` | RootBundle v2 for two generations: device envelopes, signature, the three on-chain digests, commitment and previous-root link | `root::tests::opens_exported_bundles` |
| `channel-v1.json` | One channel epoch: rotation envelopes and manifest, key confirmation, a message, a history grant and an attachment | `tests::opens_channel_*` |
| `inbox-v1.json` | The inbox key object ID and a letter envelope | `tests::opens_inbox_letters` |
| `cloud-v1.json` | `dmsg-cloud/1` device command and HTTP PoP (COSE_Sign1) | `cloud::tests::reproduces_commands_and_http_proofs` |

```sh
cargo test -p dmsg_client -p dmsg_protocol
pnpm --dir src/dmsg_frontend exec vitest run src/lib/login
```

## Generation

The extension files are frozen. The extension's `tests/client-vectors.test.ts`
(the `generator` named in each file, at ic-panda `37451040`) ran its real engine
and primitives with `crypto.getRandomValues` replaced by a SHA-256 counter
stream keyed by the test name and `Date` fixed at `1760000000000`, so every
artifact, including HPKE ephemeral keys and the IBE seed, was reproducible;
`cloud-v1.json` came from its `tests/cloud.test.ts`. Nothing in the repository
regenerates them now; the Rust tests open or reproduce them byte for byte. `connect-v1.json` comes from the `dmsg_client` connect tests (`DMSG_WRITE_CLIENT_VECTORS=1 cargo test -p dmsg_client connect`); its P-256 signatures are RFC 6979 and its HPKE ephemeral keys come from the recorded `ekm`, so it is reproducible. `legacy-v1.json` comes from `src/dmsg_legacy/tests/vectors.test.ts`
(`DMSG_WRITE_CLIENT_VECTORS=1 pnpm --dir src/dmsg_legacy exec vitest run tests/vectors.test.ts`);
its HPKE seals are random, so both implementations check it by opening it. `login-v1.json` comes from the `dmsg_protocol`
login tests, which compare it on every run and rewrite it with
`DMSG_WRITE_CLIENT_VECTORS=1 cargo test -p dmsg_protocol login`; its
delegation signature is a placeholder that fixes only the encoding. The private relay keeps its own copy
(`dmsg-core/interop/cloud-v1.json`); change both together.

## Conventions

- `*_hex` fields are lowercase hex; base64url strings appear exactly as on the wire.
- A typed value is the JSON form of one CBOR item, as in
  [`protocol_vectors.json`](../../../src/dmsg_types/tests/protocol_vectors.json):
  `{"uint": "1"}`, `{"int": "-1"}`, `{"text": ""}`, `{"bytes": "00"}`,
  `{"bool": true}`, `{"null": true}`, `{"array": []}`, `{"map": [[k, v]]}`,
  `{"tag": 2, "value": ...}`. Map entries are listed in source order; the
  canonical encoding sorts them.
- A context or AAD is `{"value": <typed>, "hex": <canonical bytes>}`. Readers
  must build it from record fields and match `hex`, not decode `value`.
- Objects other than `chunk_rules`, `seal` and `hpke` used engine-chosen keys
  and nonces; readers verify them by recomputing every context and digest and
  opening the ciphertext with the recorded key or seed.

## Not covered here

- **Device-local storage** (`dmsg/local-key/2`, `dmsg/device-bundle/1`, journals,
  job records, the WebAuthn PRF path): the desktop keeps its own SQLite storage
  and OS keychain, so these are not byte contracts.
- **Rules owned by the Rust crates**: approvals, COSE statements, account
  mutations, root digests, payment and agent formats have their own vectors in
  `dmsg_types` and `dmsg_protocol`.
- **The IBE recovery envelope** is a real vetKD round trip, covered by the
  PocketIC tests; `root-v2.json` only fixes its bytes inside the bundle.
- **Frozen-source certificates** (snapshot and folder proofs): they are real
  IC certificates of frozen old canisters, covered by the PocketIC end-to-end
  test `desktop_legacy`; `legacy-v1.json` fixes only the digests built on them.
- **The browser bridge** was removed with the extension; see
  [dmsg-connect/1](../../../docs/protocol/connect-v1_zh.md).
