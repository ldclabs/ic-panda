# 团队钱包桌面实现与验收（2026-10-22）

本文描述公开源码中的实际实现。产品与协议依据见 [wallet_zh.md](protocol/wallet_zh.md)、[钱包 README](../src/dmsg_wallet/README.md)；私有设计的定位规则见 [AGENTS.md](../AGENTS.md)。不把本地测试等同于主网部署或外链实测。

## 使用流程

**当前开放状态（2026-10-22）**：团队钱包正在调整，桌面端暂停新建。无钱包页面仅显示暂停说明，已有钱包页的新建按钮禁用；桌面窗口不能发起创建、报价或报价预览请求。统一开关位于 `src/dmsg_desktop/src/shared/wallet-availability.ts`。已有钱包、加入钱包、历史激活任务的继续处理和退款仍可用；本次不修改 CLI、daemon 或链上工厂的创建能力。下文保留重新开放后的创建流程说明。

桌面钱包按概览、提案、资产与地址、成员与策略、审计、运行管理分区。新建、加入、转账复核和管理提案各有独立步骤；独立审批窗口仍是成员决定与设备协签的唯一桌面入口。

- 新建先检查设备的 `WalletApprove`、账户冻结状态、服务登记和付款身份余额。执行创建任务时，先在 user home 完成批准核验，再发送激活付款；原付款日志继续负责重试去重。
- 新建预检的付款余额与手续费通过匿名公开查询读取，不受登录 delegation 的 canister targets 限制。登录时将配置的 hub 所指定的 ICP 账本加入 targets，供登录身份支付激活费；已有登录不会自动扩权，更新客户端后须通过浏览器重新登录一次才能取得此前遗漏的 ICP 付款权限。重启应用或快速解锁只恢复原登录，不更新其 targets；因此可能出现余额查询正常、批准后付款前的手续费查询被拒绝（`UNAVAILABLE`），这时应重新登录后重新创建请求。
- 转账以资产单位输入，使用字符串和整数精确转换；未知精度明确使用原子单位。ICRC、ERC-20 与 SPL 保留账本/合约/mint 身份。手续费标明实际扣费资产，客户端估算费用和余额，钱包的 `preview_intent` 返回当前政策要求。预览不占用资金；真正提案、批准、执行仍重新校验。
- 提案可分页、按编号查看，按本人待批准和待执行筛选。详情展示完整意图、成员投票、Agent 来源、计划、回执、交易 ID。角色、本人已投票、冻结和期限共同决定按钮是否可用。
- 成员、策略、地址簿、地址、协签人、解冻、充值、升级与代码锁定使用有类型的管理表单。Renderer 没有任意 `wallet/propose` JSON 通道；`wallet/change` 仅解析已知管理动作，链上权限和审批规则不变。
- 收款详情核对派生地址后生成二维码；ICP 同时提供 owner、subaccount 和 legacy AccountIdentifier。旧式地址只是收款表示，不改变钱包的持有账户。
- 冻结先说明影响；解冻通过既有管理员阈值与延时。已签交易优先重广播；替换交易是独立动作，继续使用原意图的手续费上限。未确认、RPC 失败和执行结果未知分别呈现。
- 本机协签密钥可要求硬件，软件回退明确标识。生成、登记、绑定地址、轮换是不同步骤；不会把“生成了密钥”显示成“钱包已启用协签”。
- 登记密钥后直接打开登记提案，批准生效后才可绑定地址。空选择和未变化的策略不能提交；移除协签必须显式选择，并展示旧阈值、协签人及完整地址。仍被地址策略引用的密钥或成员不能移除，须先通过独立提案调整地址策略；启用仅硬件协签前检查所有地址的阈值仍可满足。
- 审批窗口在刷新或重新聚焦时重查钱包批准资格；临时网络故障或权限变更后，也可在原窗口重试。
- 刷新登录权限可从侧栏顶部账户菜单选择“退出登录”，然后通过浏览器登录；CLI 为 `dmsg logout` 后 `dmsg login`。退出会清除当前账户保存的登录和快速解锁凭据，保留本机加密数据、设备身份与其他账户。

## 多设备协签

`wallet/cosign` 读取已有计划并重新独立解码，生成用户审批请求；它不另造不同计划。协签包绑定版本、钱包、提案摘要、计划编号及计划承诺，每个签名绑定对应待签摘要。ICP 使用计划 0 与提案摘要。

`wallet/cosign_import` 重新读取钱包与提案、核验计划与期限，并逐个核验签名、协签人资格和硬件要求。导入只收集签名，不执行交易。每个协签人必须覆盖该计划的全部摘要才计入人数，重复导入不增加人数。达到阈值后由 `wallet/cosign_execute` 单独执行。新计划需要新的协签，旧计划的包不能移用。

协签包可通过复制与粘贴在设备间交换，不包含私钥。本机收集状态以 LDK 加密保存。现有可生成的密钥为 macOS Secure Enclave P-256 或软件 P-256；其他硬件后端见下文独立工作包。

外链协签先准备计划，再由各设备收集同一计划的签名，满足要求后单独执行。重复准备复用有效的未签计划，不消耗新的计划编号；已过期或已签计划才创建下一版。详情可选择已有有效计划，随钱包刷新更新远端状态，并显示收集失败的原因。“仅收集签名”的审批不会承诺自动执行或广播。

通用 canister 调用可能通过转账、授权额度或其他方法使用 ICP 子账户，因此必须满足钱包内所有受保护 ICP 地址的协签策略，不能借 `CanisterCall` 绕过地址限制。同一个密钥可满足多个地址策略，但每个策略的阈值独立计算。ICP、ICRC 和通用调用的协签都绑定计划 0 与提案摘要。

本机硬件签名先在同步步骤取出密钥句柄，再在客户端锁外等待用户确认；同一密钥的一批摘要共用一次在场确认。等待期间仍可读取或锁定客户端，锁定后返回的签名不写回。签名前后重新读取提案与钱包状态；本地签名包校验和 canister 执行使用同一套按摘要顺序推进的 FIDO2/WebAuthn 计数器规则。

已签或已广播提案的替换计划收齐协签后，可以显式执行该计划；已签过的计划继续使用重广播入口。ICP 协签执行响应丢失时，客户端对已经进入 `Executing` 或 `Settled` 的提案复用链上的幂等执行接口恢复结果，不重新要求协签，也不重新付款。

## 客户端与 daemon

钱包网络操作集中在 `dmsg_client::wallet::ops`，通过 `Hold` 的同步步骤读写客户端。daemon 对同一钱包的变更取独立执行锁，钱包批准任务也按独立资源串行；等待 canister、账本或 RPC 时不占住全局 Client。付款日志保持固定参数、未知结果重发与账本去重语义。锁定后不把等待中的钱包密钥重新写回缓存；切换账户与锁定同时清除链连接缓存。

桌面请求使用账户与钱包读取代次，忽略旧响应；切换钱包立即撤下旧对象，转账草稿按钱包分开。本地时钟驱动延时与到期状态，聚焦与有界轮询更新远端状态。余额标明来源和读取时间，钱包审计头变化会使旧余额与审计结果失效。退款查询失败保留错误，不伪装成空列表。

新增 daemon 方法：

| 方法 | 行为 |
| --- | --- |
| `wallet/activation`、`wallet/activation_continue` | 独立读取付款/创建/安装/终态；继续已授权安装，尚未开单时对原报价重新请求批准并复用付款日志 |
| `wallet/readiness` | 批准资格；`funding: true` 同时读取付款身份和 ICP 余额 |
| `wallet/assets` | 按资产身份缓存 symbol/decimals；失败保留未知状态 |
| `wallet/preview`、`wallet/transfer` | 转账预检与提交已复核的结构化草稿 |
| `wallet/change` | 已知成员、策略、地址簿、地址、协签、充值与运维提案 |
| `wallet/book` | 地址簿分页；游标是 canonical Destination 的编码 |
| `wallet/receive` | 经核对的地址、二维码与 ICP 账户表示 |
| `wallet/versions`、`wallet/health` | 已登记模块、当前版本及资源状态 |
| `wallet/upgrade`、`wallet/lock_code` | 只执行钱包已经接受的 hub 操作 |
| `wallet/rpc`、`wallet/rpc_set`、`wallet/rpc_check` | 当前账户在本机的链端点配置与诊断；不能更改 IC 根、hub 或其他部署信任参数 |
| `wallet/audit_page` | 增量核验及历史页面；导出的是明确范围的一页核验记录 |
| `wallet/cosign`、`wallet/cosign_status`、`wallet/cosign_import`、`wallet/cosign_execute` | 现有计划的协签、收集与独立执行 |
| `wallet/prepare` | 准备或复用外链的有效未签计划，不触发设备签名或执行 |
| `wallet/channel`、`wallet/notify` | 本机账户的通知频道绑定与重试 |

RPC 配置只允许 HTTPS；Local 环境额外允许回环 HTTP，拒绝 URL 用户名/密码。诊断 EVM 端点还核对实际 chain ID。资产元数据是显示与输入换算信息，不是对代币经济价值的认证。

## 审计与频道

审计缓存保存已核验的链头、长度与每 200 条的检查点。每次以新认证的钱包链头为终点校验增量；历史页从已核验的检查点校验到另一个已核验检查点。导出包含范围、前后哈希和核验时刻，不声称单页就是完整历史证据包，也不把审计链完整性当成外链结算证明。

钱包变更可在绑定频道发送 `dmsg-wallet-event/1` 加密消息。消息 ID 绑定钱包与审计头，重复发送可去重；频道不可用不回退已经完成的钱包操作，而是在结果中保留 `notification_error`。频道卡片只提供导航，收件人必须重新读取钱包状态。消息正文不能直接批准、执行或更改钱包。`dmsg://wallet/<principal>/<proposal?>` 同样只导航。

## 部署与验证边界

新增 canister query `preview_intent(Intent) -> Result<Requirement>` 已进入 Candid，**使用新版桌面转账预检时，需要同步构建、登记并升级钱包 Wasm**。本次源码提交不自动部署生产钱包，也不发布治理提案。

协签检查、计划复用及策略校验的修复同样需要升级钱包 Wasm；仅更新桌面或 daemon 不会改变已有 canister 的执行规则。本轮未增加或更改 canister Candid 方法签名。

自动测试覆盖：精确金额和标识、角色矩阵、时钟、旧响应隔离、完整策略审批、提案分页、表单预览失效、慢网络下本地请求可用、独立 ICP 账本的首页预检与激活付款、登录 targets 外的公开余额查询、无 WalletApprove 不扣款、双成员 ICP 转账、两个独立 daemon 的 P-256 2-of-2 协签与审计核验。Electron 测试使用模拟 daemon，PocketIC 使用测试账本与私有中继；它们分别证明窗口接线和客户端/canister 闭环。

真实外链广播、真实硬件协签、完整屏幕阅读器和各平台桌面发布仍需要独立验收。实际运行命令与本次结果以提交说明为准，未执行的检查不计为通过。
