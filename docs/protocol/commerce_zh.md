# dMsg commerce 2

状态：开发接口已经实现，生产配置、真实身份与资金验收需单独留证。完整字段和方法见 [英文规范](commerce.md)、[集成协议](integration.md)、[动作签署](app-action.md) 与 [浏览器 v4](browser-v4.md)。不提供 commerce 1 的订单、会员变更或买断回退接口。

## 权威与身份

产品负责本身的账号/项目、USD 账单、角色、共同合同和交付回执；dMsg user 核验精确账号/设备批准；commerce 核验真实资金；membership 维护神经元资格、全局占用与全额抵扣承诺。浏览器和 Worker 不是这些事实的权威。

受益主体是 `(product_id, authority_canister, subject_schema, subject_bytes)`。dMsg 账户、产品操作人、受益主体与实际经济钱包是不同字段。TokenList 使用八字节大端 ProjectId，dMsg 自用账号和参考账号产品分别使用自己的十二字节 schema。长度不能决定账号归属。

`BillingOffer` 固定完整美元微单位金额、`[S,E)`、SKU、原条款摘要、业务版本、operation ID、quote authority 和 adapter。服务回读已登记产品权威；前端传入金额和日期不能替代它。报价不占区间或成功申请名额。条款摘要取产品注册的 `terms_hash`，条款随注册更新生效，与目录排期无关。

产品注册列出一组受益权威，只能追加。主体指明其中一个，checkout 与 membership 向该主体自己的权威请求 `authorize_product_billing`。dMsg 账户产品列出每个 user home，新增 home 的账户同样可以购买。

## 现金

生产只支持 ckUSDT `cngnf-vqaaa-aaaar-qag4q-cai` 与 ckUSDC `xevnm-gaaaa-aaaar-qafnq-cai`。资产身份由 ledger 确定，不由 symbol 推断。两者要求验证 decimals=6、ICRC-1/3、费用和真实 transfer 块格式。价格观察有明确 authority、最多 30 分钟有效期及 1% 脱锚守卫，没有隐式一美元价格。

`amount_atomic = ceil(amount_usd_micros × 10^decimals / price_usd_micros)`，中间乘积使用大整数，只在最后向上取整。报价冻结商户、账本、payer、收款子账户、价格、网络费上限/储备及资金期限。之后发布的新价格不会使已接受报价失效：只要报价自带的价格观察仍在有效期内、当前观察同样可用，且账本、资产类型、精度、费用和启用状态等非价格条款未变，`open_checkout` 仍按原报价开单。

开单还必须以 `(ledger, policy_version)` 精确匹配稳定存储中由价格权威发布的快照；客户端提供的价格、观察时间和版本不能证明其真实性。每个账本最多保留 256 个仍有效快照，发布时清理过期快照；满额时拒绝发布，不挤掉仍有效的旧报价。治理更新已登记资产时只替换非价格条款：沿用最新发布的价格并取下一个版本，提案等待期间的价格发布不会使它过期。

现金订单、出金腿和资产政策没有认证叶，读取是带权限检查的普通查询，用于展示和恢复。资金只按账本证据和冻结报价移动，`open_checkout` 会按价格历史重新核对报价引用的资产政策。

`quote_checkout → approve_application + 产品批准 → open_checkout → AwaitingFunding → 钱包原转账 → check_checkout_funding → Apply/原回执`。

账本与其认证 archive callback 提供入账事实；去重键为 `(ledger, block_index)`。只有选定资产、预期付款人、足額及时的一笔入账可以开通。错资产、错来源、不足、多付、重复及晚到资金留作实际来源的退款义务。

每笔订单分别维护每个账本：

`incoming = refundable + service_reserve + fee_reserve + outgoing`。

商户只能领取自己原订单的已赚部分，从 `max(实际交付时间,S)` 起算。另一商户或另一资产不能替它支付。未开始的现金续费可凭产品取消回执退款；已开始的服务没有新增任意退款承诺。

转出记录冻结 ledger、来源、接收人、金额、fee、memo 和纳秒时间。Unknown 只能用原参数或可信原区块对账；不能创建第二笔付款。已知失败的出金腿只能由接收者明确批准后重发：使用新的账本时间戳，保留原 fee 或采用账本给出的 fee，并受原 cap 约束，不增加总资金义务；超过账本 24 小时去重窗口才派发的腿也由此恢复。超限继续 FeeBlocked。

商户每次归集最多用一笔账本 fee 的费用准备补贴。完成全部已赚收入的那次归集会一并带走无法单独退回的准备金余额；更大的余额在收入全部归集后退回冻结的付款人，任何人都可以触发。这样结清的订单余额归零，可以归档。在途转账、对账和修订共用内存调用 guard；旧回调尚未结束时，等待超过一分钟也不能并发派发。升级只丢弃 guard，保留 `InFlight` 和冻结参数，由原账本结果裁决。

## PANDA 全额抵扣

`required_stake_e8s = ceil(amount_usd_micros × R_num × 10^8 / (10^6 × R_den))`。

金额是完整订阅区间价格；不按天数年化或按剩余期限降低门槛。R、门槛、申请期限和原 E 固定到接受的条款。没有 USD 补贴预算；新增申请受同时在用申请上限与每小时申请上限约束。只抵扣全额订阅费，客户现金本金为零；没有折扣 bps、部分抵扣、买断或可提现余额。

服务验证固定的 SNS root/governance/ledger 和八位 PANDA 精度，不固定 governance 模块：SNS 自行升级到 NNS 批准的版本，无法解码的 `get_neuron` 回复为 Unverifiable。实际 actor 只需列在神经元的 principal 中，权限不限（例如热键）；其他 principal（包括神经元所有者）的权限也不限，全局占用保证一个神经元不会同时支撑两份权益。净本金足额且最早解锁时间不得早于 E，使神经元在整个付费区间 `[开始, E)` 内保持锁定。dMsg 不取得 SNS 原生托管权。同一申请一分钟内复用上次观察，不重复查询 SNS。

首次实际合格观察后至少冷却 65 分钟，再用新鲜账号/产品批准和神经元观察确认原条款。一个全局占用表阻止同一神经元跨产品/主体复用；同一主体只可同时持有当前与连续下一期引用。

激活使用的观察起点必须不早于冷却截止；一分钟缓存不能复用冷却结束前的观察。SNS 配置同时只派发一个核验，其他请求返回 Pending，稍后重试复用缓存；失败后可重新核验。新费率版本严格递增，旧政策清理后也不能复用版本号；保留版本的同内容重试使用原发布时间，不重新计算公告期。

Apply 准备之前可取消；Apply Unknown 不按超时释放。Apply 成功后，即使未来续费尚未开始，也不可提前退出、Replace、Buyout 或 Close。解绑、产品结束、失格和权益终止不缩短 `committed_until=原 E`。每个到期引用只释放一次，不误清连续下一期。

资格租约最多一小时且不越过 E。已知失格停止新权益并进入七天修复；Unverifiable 暂停修复时钟、不延长旧租约。终止权益永不复活，占用仍到原 E。读取神经元期间 SNS 配置核验过期（一小时）或失败时，回调不发放新租约，也不清空承诺。

产品预留返回暂时不可用、结果未知、Pending 或配额不足时，保留原申请供对账。预留、查询原回执、Apply 和释放各自在实际派发时消耗产品调用预算：每 UTC 分钟全局 `product_calls_per_minute` 次、每经济 actor 10 次。报价与申请共用 `authorizations_per_minute`，激活另有同样大小的预算，报价不会挤占已接受申请的激活。三项预算都由 `PandaServiceConfig` 治理，配置之前各为 200。同一申请已有在途产品调用时返回 Pending；本地幂等读取不扣额度，暂停准入时恢复预算仍生效。

完整终态保留至“终态转换时间与申请截止两者较晚值 +30 天”。每次 sweep 最多释放 32 个到期承诺，并压缩 32 个到期终态；返回两者之和，维护任务重复调用到返回 0。压缩移除完整记录、读者索引和认证叶，保留原操作及条款摘要；之后原样读取/重试返回 ResultExpired，同 ID 不同条款仍报 IdempotencyConflict。未决 Apply、仍占用神经元的 Active/Terminated 不清理。完整记录上限 100 万，包含摘要的历史操作总量上限 1,000 万；这些是防护上限，不代表生产容量验收。操作分页使用读者索引，只有还存在可读完整记录时才返回游标。

## 产品适配与资源

两种方式共用 `ProductBook` 的区间预留和业务 CAS；Unknown Apply 不会被 prune。固定 callback caller、完整报价/来源、当前角色和版本都要核对。原决定、合同和回执原子保存；ACK 丢失查询/重放原决定。资格观察只增加 lease revision。

TokenList 保留首次结算的 Included 期、年度档位和续费窗口；外部订阅历史保存实际 dMsg 来源，不在本地再次 transfer_from 或增加原生可提现收入。Worker 付费起草通过 registry 只读共识方法核对已认证 signer 与当前来源租约。

dMsg 自用产品也通过同一服务获得合同。现金升级和存储增购投影为资源，不能退出 PANDA。升级沿用原年度起点，升级差价和存储包都按该完整年度的剩余时间折算；过期存储包不计入 64 个上限。不可核验与已知失格期间都暂停付费执行时间，已知失格的权益视图带修复截止时间。月度执行额度按完整、无重叠 UTC 时间线加权，账户创建前无额度；资格刷新和退款不重置已用/预留单位。根派生与恢复使用独立安全预算。Free 月额度按实际生效的目录时间线分段，旧租约不跨越下一次目录生效时间；刷新后推进租约版本。

资源租约长度取决于权益能否被收回：已开始的现金服务没有退款，未开始的续期在下一个边界之后，因此现金、已到期和 Free 租约最长 30 天，并在下一个已知额度变化点截止；PANDA 资格可能丢失，由 PANDA 支撑的租约不超过一小时。租约剩余不足 10 分钟才重新签发，membership 在同一窗口内重新核验合格的认领，所以提前几分钟续期的消费者能拿到更晚的租约。membership 返回 `Pending` 或 `QuotaExceeded` 时没有读取 SNS，原租约继续有效，也不会开启付费时间暂停。user home 至少每小时重新核对一次执行额度，与资源租约长度无关。

从未购买的账户没有 commerce 记录和认证权益叶：不存在证明加认证目录即为 Free。它的执行额度由目录和 home 提供的账户创建时间计算，租约版本为 0；已保存主体从版本 1 开始。账户工作记录只保留当前月所需及仍有效/未来的资源区间，并保存最后服务截止时间，不重复保存无限历史月账。

公开记录、定期报告和重大变更披露不会被计费故障阻断。缺失或过期租约不授予新增值权益。

## 恢复与发布

运营界面通过读者索引分页列出当前身份可读的原订单、转账、每账本义务、过期资格和原到期承诺；商户以订单冻结的商户身份读取，只有还有可读记录才返回游标。`checkout_deposits(order_id, after, take)` 提供最多 128 条入金的游标分页。没有清空 Unknown 的按钮。商户用 `collectable_checkouts(after, take)` 按服务终点分页仍有未归集收入的 `Applied` 订单，每期归集一次的任务遇到第一个服务期未结束的订单即可停止；`commerce_stats` 报告实时记录数、稳定内存和 cycles，供与 `get_commerce_limits` 对照。暂停只阻止新申请，旧对账、原路退款、资格刷新与到期释放继续可用。

Rust、SDK、真实 PocketIC、两个产品类型与临时 Chrome profile 有独立验收。真实 II/钱包 origin、经济权限、治理 R 及真实资产付款/退款需生产证据，不能用本地 fixture 代替。历史 Statement 三个 profile 的字节不变；消息投递仍使用独立 delivery profile 2，不构成订阅旧接口或 PANDA 退出通道。

## Checkout 维护与存储

资金查证、产品调用和出金共用治理可调的每 UTC 分钟全局额度（初始 400 次）和治理可调的每 caller 份额（`calls_per_caller`，初始 40 次），账本查证包含有界 archive 跳转；授权独立限制（初始全局 200 次）、每 caller 10 次。资格刷新有治理可调的全局额度（初始 200 次）、公开 caller 20 次，登记的 user home 可为其账户使用全部全局额度。回执查询与需要的 Apply 分别计入实际产品调用；本地退款分配、终态读取和被 guard 拒绝的并发重试不消耗 RPC 额度。最多同时保留 128 个在途 guard。

`sweep_checkout_history` 每次最多归档 32 个订单和 32 个出金腿。订单必须没有退款/履约/手续费义务、未完成出金或未知产品结果，且超过最后资金变动与服务/激活截止较晚者 30 天；成功或已替换的出金腿保留至少 30 天。未知、待派发和待修订出金不归档。

归档订单压缩冗余授权与决定正文，保留原输入摘要、完整报价、每账本余额、最终回执及入金引用；入金去重与读者索引不删除。历史详情及分页仍可读。新的真实迟到款会把原订单恢复为热记录并原路退款，不重新授益。主体、热订单、累计订单身份、每日订单和每分钟调用的准入上限由治理在固定上界内设定，恢复旧款不受新开单额度阻断；容量 profile 记录这些上限背后的实测成本。

一次部署可以运行多个 commerce canister：各实例列出互不重叠的 user home，各自持有注册、资产、目录和订单，并作为其 home 的 `dmsg_user` 的 `commerce_canister`。共享的 membership 在 `PandaServiceConfig.commerce_homes`（只能追加）中记录每个 user home 的 commerce，并以 `qualifications_per_minute` 限制 SNS 读取；私有云端按账户 home 的 commerce 验证目录与权益证明。
