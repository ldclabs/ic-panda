# dMsg 桌面端界面设计：门房（Gatehouse）

- 范围：`src/dmsg_desktop` 的主窗口与审批窗口，以及网站 `/legacy` 的迁移面板。
- 日期：2026-10-16 提出并获批；同日按 P0–P6 实施完毕。
- 实现：`98edf38a`（P0–P2）、`c95b6ab2`（P3）、`9aac7b7a`（P4）、`b1a14a22`（P5）、`6c90b43e`（P6）；网站 Remix Icon 许可修正 `ac477f9b`。
- 设计系统细则（令牌、字号、组件约定）见 [src/dmsg_desktop/DESIGN.md](../src/dmsg_desktop/DESIGN.md)；令牌源自网站的 [src/dmsg_frontend/DESIGN.md](../src/dmsg_frontend/DESIGN.md)。
- 本文记录方案及其实施状态。设计与实现不一致时以代码为准，并同步修改本文。

## 1. 概念

dMsg 的标志是一道门：门柱、门顶，以及等在门口的一颗菱形请求。桌面端就是这道门的门房：保管秘密库和频道，接待网页、终端和 Agent 送来的请求，由人决定是否放行。品牌色、Paper 底色和 Gate 标志早已到位，需要重做的是结构、层级和交互。方案的三根支柱：

1. **门栏：状态常驻。** 锁定、待同步版本、后台在线、daemon 连接和待审批数，固定在侧栏，不再只出现在设置页。
2. **工作台：对象优先。** 列表加检查器取代卡片堆叠；新建、导入、转移进弹层和分步对话框；⌘K 统一搜索、跳转和命令。控件全部来自 bits-ui + Tailwind CSS 组件库。
3. **票据：放行有仪式。** 审批窗口先讲谁在请求、经过哪条链路、签的是什么、批准后会怎样，技术细节折叠；付款和撤销设备要按住确认。

## 2. 改版前的诊断

依据 2026-10-16 冒烟测试截图（`131f8a95`，示例数据）。颜色没有错，是结构让界面显得简陋：

| 编号 | 问题 | 表现 |
| --- | --- | --- |
| F1 | 页面是表单的堆叠 | 列表、详情和新建表单纵向排开；设置一页装下八个主题；没有"当前对象"，找东西只能滚动。 |
| F2 | 最重要的状态最不显眼 | 锁定状态是侧栏底部一行灰字；待同步数和后台在线只在设置页出现，用户不知道内容是否已离开本机、何时会被锁。 |
| F3 | 按钮没有层级 | 每行一个红色"删除"，常用操作排成一排，危险操作反而最醒目。 |
| F4 | 标识符直接裸露 | 20 字符账户 ID、64 字符设备 ID 混在正文，长串换行挤坏布局。 |
| F5 | 协议词汇直接上屏 | "Epoch ≥ 2"、`discourse.read:https://…`、"Grantable: …" 是第一层信息。 |
| F6 | 审批窗口没有重心 | 标题是应用 ID，字段等权排列，转述来源只是一行棕色字，批准与拒绝是两个小按钮。 |
| F7 | 缺少桌面应用的基本功 | 导航无图标，没有快捷键、全局搜索、右键菜单和通知，时间格式统一冗长，窗口用系统标题栏。 |
| F8 | 原生控件 | 复选框、数字输入、textarea 是浏览器默认外观；网站 `/legacy` 有原生下拉、方角密码框和未套样式的次要按钮。 |

## 3. 借鉴 anda-bot chrome-extension

anda-bot 扩展（0.14.2）与桌面端同为 Svelte 5 + Tailwind CSS 4 + bits-ui 2，组件写法可以直接移植。

**借鉴：** 可折叠侧栏与带图标块的顶栏；`ui.ts` 用 `cn()` 组合按钮变体与尺寸，页面只组合不写散装样式；标题栏、底栏固定而正文滚动的唯一 Modal；"筛选 / 主体 / 检查器"三栏工作区；审批卡片的类型图标块；弹簧与缓出两类动效曲线及进行中的文字微光，减少动态时全部停下；系统 / 浅色 / 深色三态主题与本地打包的 Inter Variable；斜杠命令面板演变为 ⌘K。

**不照搬：** shadcn 中性灰（dMsg 用 Forest Ink、Paper、Forest Green 和 Gem 琥珀）；Lucide 图标（只用 Remix Icon 一套）；以对话为中心的布局（只有频道和收件箱需要对话形态）；常驻的呼吸光晕与彗星描边（敏感流程不用催促式动画）；10px 圆角（沿用 8 / 12 / 16 三档）。

## 4. 设计原则

用来裁决每一个界面的六条规则：

- **R1 状态先于内容。** 锁、同步、待决请求永远在同一个位置，用图形和文字同时表达，不只靠颜色。
- **R2 一个对象，一个位置。** 选中即在检查器展开；新建、导入、转移进弹层，不和列表抢地方。
- **R3 标识可认、可查、可复制。** ID 以首尾各 4 位的中性胶囊显示，悬停看全文，点击复制。缩写相同不等于同一个 ID。
- **R4 先讲后果，再给细节。** 审批、授权、转移先用一句话说明会发生什么，原始字段折叠在下面。
- **R5 危险操作要多费一步。** 默认焦点在拒绝；批准键在请求出现后短暂不可用；付款、撤销设备、恢复与签名策略要按住确认。
- **R6 动效只表达因果。** 弹出用弹簧，到达用缓出，进行中用微光；按钮不移动、不闪烁；减少动态时全部静止。

## 5. 主窗口

### 5.1 骨架

侧栏管去处，门栏管状态，检查器管对象。

- **侧栏**（236px，可折叠为 64px 图标栏）：顶部账户切换器（本机账户；未登录时为"登录"，否则"用其他身份登录"）；中间按"工作 / 授权 / 账户"分组；设置单列；底部门栏。未导入的旧版迁移显示一条可关闭的提示。
- **门栏**：未解锁时显示锁定状态和打开设备的下一步（未登录为主按钮"登录"，已锁定为"用 Touch ID 解锁"、"快速解锁"或"登录"：快速解锁在每次登录解锁后默认开启，可在"设置 › 会话与账户"关闭，该处显示人在场验证的方式与登录到期时间；Secure Enclave 保管密钥时，主窗口在锁定状态下来到前台（或在前台打开）会自动请求一次 Touch ID，拒绝后不再自动请求，人刚在窗口前锁定时也不请求；锁定视图另有"用 Internet Identity 登录"；未开启时锁定视图说明解锁需要登录并指向该开关，尚未建立或加入账户为"继续设置"；暂不能显示的视图给出同一步）、待同步版本数（点击立即同步，进行中显示微光）、后台在线（开启时常驻）与 daemon 连接；解锁后不再重复显示"已解锁"状态行，只保留底部的一个"立即锁定"按钮。
- **顶栏**：图标块、视图名与一行说明、设置子页的面包屑、⌘K 入口。侧栏顶部与顶栏同高，放窗口按钮：折叠侧栏、后退、前进，后两者在本窗口看过的视图间往返。macOS 上窗口不用系统标题栏，红绿灯悬在侧栏材质上，窗口按钮紧随其后；全屏时红绿灯隐藏，按钮移到边缘；关闭全屏中的主窗口时先退出全屏再隐藏，避免留下黑屏的空间。侧栏折叠后顶栏伸到图标栏上方并接过窗口按钮，位置不变。参照 anda-bot 桌面端。
- **快捷键**：⌘K 命令面板，⌘1–⌘8 与 ⌘, 切换视图，⌘L 锁定，⌘[ 与 ⌘] 后退、前进，秘密库内 ⌘N 新建、⌘F 搜索（其他平台用 Ctrl，后退、前进用 Alt+← 与 Alt+→）。
- **命令面板**：跳转、会话命令、外观和语言；输入后可按标题找到秘密库条目。
- **登录对话框**：所有入口（门栏、锁定视图、账户菜单、命令面板、设置、绑定登录）共用一个流程，分三步显示：打开登录页、在浏览器中用 Internet Identity 登录、在这台设备上完成；附登录页有效期、"重新打开登录页"与"复制链接"。窗口在 daemon 的 `login/changed`、`session/changed` 事件上读取 `session/login_result`，不轮询。失败时说明原因（网络不可用、浏览器中取消、过期、被拒绝），附 daemon 的原始信息与"重试"；关闭对话框后在浏览器完成的登录照样生效。首次登录尚无账户时转到设置。

### 5.2 各视图

| 视图 | 结构 |
| --- | --- |
| 秘密库 | 筛选栏（全部、收藏、类型、标签、回收站）+ 列表 + 检查器。行有右键菜单；字段旁边放各自的操作；编辑在检查器内完成并写明替换的版本。秘密第一次点击后变成"再点一次"，3 秒内有效，按钮底部细条显示剩余时间；显示 1 分钟后自动隐藏；复制经主进程进剪贴板，30 秒后清除。新建在对话框里选类型卡片、加标签、可生成密码。冲突副本并排对照，正文逐行标出差异。文件可从对话框导入或拖到列表，导入按"加密 → 校验 → 中继保存"显示进度。 |
| 频道 | 频道列表（按最近活动排序，显示最后一条与未读数；已归档、已退出、已隐藏的收在下方）+ 按天分组的时间线与输入框 + 成员抽屉。成员显示其公开资料的名称。消息在中继保存前显示"发送中"，失败时留在 daemon 的发件箱，以同一消息 ID 重试或丢弃；未发送的文字由 daemon 按频道保存。消息可回复、编辑、撤回、在本机隐藏，图片在时间线中预览，往上可加载更早的消息，只在停在底部时跟随新消息并标记已读；自己的消息显示送达与已读（已读回执需在菜单中开启）。频道内搜索；附件来自文件库搜索、新导入、拖放或粘贴，可一次多个。所有权转移包直接发到频道里，由对方在时间线上接受、发起人完成；计费转移的提议即暂停频道写入，其转移包复制后交给对方。解锁时窗口不在前台会通知（可按频道静音），Dock 与侧栏显示未读数；`dmsg://channel/join#…` 链接打开加入对话框，个人资料与来信可发起两人会话。访问对话框管理本账户 Agent ID 对该频道的读写授权。成员菜单里有角色、换代权限、历史授权和移除；邀请框说明对方能读到第几代起的消息，可勾选先轮换密钥；管理菜单可立即轮换密钥，等待换代时只有能换代的人看到换代按钮。新建、加入、离开、所有权与计费转移都在对话框里，转移分三步显示。 |
| 收件箱 | 收件箱 / 已发送 / 已归档与阅读区两栏；写信与"谁可以给我写信"（单选卡片：不接收、联系人、所有人、付费来信）在对话框里。 |
| 签名与授权 | 四个标签页。请求：待决（剩余时间、上次批准未执行的原因；本机客户端发起的可撤回）、进行中（可立即核对）、已决（按类型筛选，可只读打开）。签署：签名条件（登录、本设备正式审批及其开关、签名策略）；文本、关于文件的声明、文件摘要（本机文件只经主进程对话框，或填十六进制摘要）、应用动作；本月额度。证据包：选择或拖入证据包，逐项核验并可保存报告；账户的签名（含其他设备的）可就地核验或导出。授权：可批准的设备、已配对的浏览器、仍有效的网页会话、Agent 的能力与凭证，各自链接到管理处。锁定时显示锁定视图，证据包核验仍可用。 |
| Agent | 标签页：主体与控制者、凭据；托管的 Agent ID 与主机白名单（只读）；能力矩阵（Agent Protocols 各服务的读写与所到 origin、其他能力）与全部授权；Agent Mail 与 Knowledge；MCP Events 端点；按天排列的审计时间线。 |
| 会员与名称 | 当前方案与限额、方案卡片（读取目录的 `plan_id` 与 `limits`）、订单、名称查询与转移、钱包与支付运维。 |
| 设置 | 左侧分区，每个分区有自己的路由：会话与账户、账户安全、设备、公开资料、已连接浏览器、文件库、语言与外观、旧版迁移、关于 dMsg。 |

## 6. 审批窗口：票据

审批窗口是独立窗口，也是唯一能做决定的地方（`approval/respond` 携带所显示内容的摘要）。从上到下回答四个问题：谁在请求、请求从哪条路来、要签的是什么、批准后会发生什么。技术字段折叠在最后，决定按钮在票根上。

1. **来源链路。** 网页请求画出"网站 → 浏览器 → connect.dmsg.net → 本机"，经转述的一段用虚线；Agent 请求显示 `agent:` 与名称（本机托管的 Agent ID 显示其名称），终端显示 `cli`，主窗口显示 `gui`。
2. **内容先行。** 先显示要签的文本、文件名与摘要或金额，再显示签署身份、用途与本月剩余额度。关于文件的声明写明文件名、大小与来源（本机路径或文件库）；只有摘要时可"与我的文件核对"，由主进程选择文件、daemon 计算摘要，只记录是否一致，不改变所批准的内容。应用动作按应用登记 schema 的标题与标签（按界面语言）呈现，注明措辞由应用定义、经治理登记；schema 不再匹配时只显示原始命令与取值并提示。签名策略变更显示原值 → 新值。
3. **后果一句话。** "批准后"写清会发生什么、能否撤回；批准后立即显示"执行中"，决定后按 daemon 的真实状态分步显示结果，网页请求依次为中继授权、结果就绪、页面已取得；失败或结果丢失时写明原因，并可转到下一个待决请求。
4. **防误触。** 请求出现后批准键 1.2 秒内不可用，内容变化（例如报价到达）或窗口重新回到前台后重新计时；进度在按钮内部填充，按钮本身不动；默认焦点在拒绝。签名请求先做签名条件检查，有阻碍时禁用批准，并写明原因与去处（开启本设备正式审批、在主窗口登录、账户安全、会员方案）。
5. **风险分级（D3）。** daemon 为每个请求给出 `risk`：付款、撤销设备、绑定或移除登录、签名策略、恢复等待期、Agent 主体变更为高风险，要按住 1 秒（指针或空格 / 回车），松开即取消；Secure Enclave 保管快速解锁钥匙的 Mac 上还要以 Touch ID 或登录密码确认，拒绝后请求继续等待并显示原因。其余点击即可。规则在 daemon（`dmsg_client::approval::high_risk`），窗口与 CLI 共用。
6. **过期。** 票根上的细线显示剩余时间，最后一分钟变为琥珀色，不闪烁；过期后按钮失效，并向 daemon 重读状态。
7. **锁定。** 设备锁定后窗口立即清空请求内容，只显示锁定视图与解锁入口（快速解锁，或在主窗口登录）；在锁定状态下打开时先请求一次快速解锁。解锁后重新读取请求。

- 动效三条曲线：弹簧给弹出的东西（通知、单选圆点），柔和弹簧给到达的东西（⌘K、对话框），缓出给移动的东西（侧栏折叠、折叠面板）；菜单与提示用淡入缩放。

## 11. 不变的安全约束

- 只有审批窗口能做决定；主窗口调用 `approval/respond` 或 `decide` 一律被拒绝。主窗口可撤回本机客户端发起的请求（`approval/cancel`），这不执行任何操作。
- 窗口不能指名本机文件：`attest/request` 的 `file` 参数在窗口调用中被去掉，`approval/check_file` 不在窗口白名单；本机文件只经主进程的对话框交给 daemon。
- 锁定后审批窗口不保留任何请求内容。
- 秘密只在第二次点击后显示或复制；复制由 daemon 经主进程进剪贴板，窗口从不持有。
- 文件只经主进程的打开 / 保存对话框进出；拖入的文件由 preload 用 `webUtils.getPathForFile` 取得路径，页面自造的文件没有路径，会被拒绝。
- 付款、授权、绑定登录、撤销设备等都以审批请求的形式进入审批窗口。
- 空闲锁只认人在窗口里的输入（点击、按键、滚动）与解锁成功：主进程在 `app/initialize` 声明它的连接由自己上报活动，随后至多每 10 秒发一次 `app/activity`；窗口随事件的读取不算活动，不会让设备一直不锁；主进程发完 `app/initialize` 才告诉窗口已连接，窗口的第一次读取也不算活动。窗口不能调用这两个方法。解锁成功由 daemon 自己记录：主窗口来到前台时请求的 Touch ID 没有窗口内输入。
